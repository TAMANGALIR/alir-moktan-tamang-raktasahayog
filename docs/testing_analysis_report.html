1 Testing and Analysis

Testing is a critical phase in the software development lifecycle of Raktasahayog. Testing was carried out to verify that the system operates correctly and meets all project requirements as specified in the system design. The various testing procedures were used to detect mistakes, confirm functionality, and enhance system quality. Unit testing and system testing were used to test in this project in order to cover all the modules.

1.1 Test Plan

1.1.1 Unit Testing Test Plan

Unit testing concerns small and individual aspects of the Raktasahayog system which may include API endpoints, controller logic, service methods, middleware logic, and React components. Individual testing of each component is done to ensure that it is functioning in the right manner and giving a desired response.

1. Objective
To verify that each module of the Raktasahayog system, including authentication (JWT and OTP), appointment management, blood campaign handling, payment processing (Stripe and eSewa), document uploads, real-time alerts, and emergency blood requests, works correctly in isolation.

2. Testing Method
White box testing
Tools Used: Postman, Browser DevTools (Chrome and Firefox), Prisma Studio, Manual Testing

3. Test Environment
Web browsers (Google Chrome, Mozilla Firefox), Vite dev server (frontend on localhost:5173), Node.js and Express server (backend on localhost:5000), PostgreSQL database, Visual Studio Code, Windows OS.

1.1.2 System Testing Test Plan

System testing checks the complete Raktasahayog system after all modules, including authentication, appointment booking, emergency blood requests, campaigns, payments, inventory, donor profiles, and admin management, are integrated. It ensures that the system works as a whole and meets the user requirements from the perspective of donors, organizations, and administrators.

1. Objective
To confirm that the entire Raktasahayog system is operating when all the parts (React frontend, Express.js backend API, PostgreSQL database, Socket.IO real-time communication, Stripe and eSewa payment gateways) are assembled and deployed.

2. Testing Method
Black box testing

3. Test Environment
Web browsers (Google Chrome, Mozilla Firefox, desktop and mobile responsive views), mobile devices tested in response design mode browser DevTools, production server (Vercel) (frontend installed via live URL), deployed backend API (PostgreSQL database).

1.2 Unit Testing

Unit testing was performed on individual modules of the Raktasahayog system. Each function, API endpoint, and React component was tested separately to check whether the expected output is produced. The backend REST API was tested using Postman by sending HTTP requests with a particular payload to all the endpoints. The frontend was tested manually in the browser and DevTools was used to inspect it. The following unit test cases were designed to cover all major modules of the system.
